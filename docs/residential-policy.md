# 住宅节点策略约定

确认日期：2026-10-22。来源：仓库维护者明确要求。

## 核心原则

> 宁可用户无法使用，也不要使用普通代理或低质量节点。

`住宅IP`、`ChatGPT`、`Claude` 属于住宅策略，只允许手动选择指定住宅节点。不得为提高可用性添加 `代理IP`、`PROXY`、`DIRECT`、普通机场节点或其他普通代理分组作为候选或兜底，也不得通过嵌套分组间接引入这些出口。

所有住宅节点不可用时，应排查或恢复住宅线路，不能改走普通代理。此约束适用于配置文件、示例、生成模板及使用说明；后续维护必须保留。

## 支持的节点名称

名称按实际大小写书写，其中 `Ip` 为大写 I、小写 p：

- `专属纯净静态住宅节点`
- `专属纯净静态住宅Ip-连接线路1`
- `专属纯净静态住宅Ip-连接线路2`
- `专属纯净静态住宅Ip-连接线路3`
- `专属纯净静态住宅Ip-连接线路4`

这些名称是配置兼容约定，不代表仅凭节点名称就能验证出口的住宅属性或质量。使用者应确认实际出口符合要求。

## Shadowrocket 配置

`ss.conf` 中三个住宅分组使用相同的精确名称正则，仅从客户端现有节点中筛选候选：

```ini
[Proxy]
住宅节点缺失-禁止连接 = socks5,127.0.0.1,1

[Proxy Group]
住宅IP = select,select=0,policy-regex-filter=^(专属纯净静态住宅(节点|Ip-连接线路[1-4])|住宅节点缺失-禁止连接)$
```

`ChatGPT`、`Claude` 分组采用同样写法。

- 不再静态列出五个名称，也不再用 `policy-select-name` 固定旧名称，避免引用不存在的节点。
- 正则从头到尾匹配，只接受约定的五种名称，不接受包含额外前后缀的普通代理。
- `select=0` 默认选择首个匹配的住宅节点。匹配顺序跟随客户端节点列表，正则分支的书写顺序不代表节点优先级；不是旧名称、线路1、2、3、4的强制排序。
- 「住宅节点缺失-禁止连接」是配置内定义的本地阻断候选，连接本机 `127.0.0.1:1`。本次检查该端口没有监听服务；维护者不可在此端口运行 SOCKS 代理。它不是外部代理出口。
- 当前客户端实测先列出订阅匹配节点，再列出配置内本地阻断节点；没有匹配住宅节点时只剩阻断候选。
- 不使用 `select,REJECT,policy-regex-filter=...` 来保证空匹配阻断：本次客户端规则测试仍解析到了首页节点，包括在正则中保留 REJECT 的尝试。
- 保持 `select` 手动选择，不运行测速，不因连接失败自动更换住宅出口。节点存在但不可用时，需手动换另一条住宅线路或等待修复。

### 2026-10-22 排查记录

原配置虽然移除了普通代理候选，但仍默认选择旧名称「专属纯净静态住宅节点」。客户端订阅已有线路1～4，规则测试却显示 `ip125.com → 住宅IP → 🚀【极速专线】洛杉矶CN2-线路3`，与首页选中节点一致。

因此不能把“静态候选列表里只有住宅名称”等同于“缺失节点就会拒绝连接”。本次改为筛选实际存在的节点，并加入始终存在的本地阻断候选。导入后应再次检查客户端规则测试及实际连接日志，尤其是更新前已有缓存选择的设备。

本次客户端规则测试验证：

| 场景 | 测试结果 |
|---|---|
| 当前订阅有线路1～4，旧名称不存在 | `ip125.com → 住宅IP → 专属纯净静态住宅Ip-连接线路1` |
| 临时分组只匹配本地阻断候选，模拟全部住宅节点缺失 | `住宅空组验证 → 住宅节点缺失-禁止连接` |

临时测试分组和测试域名规则验证后移除。上述是规则解析验证，不是出口 IP 检测。

## Quantumult X 与普通代理策略

Quantumult X 的住宅策略同样不得引入普通代理候选。当前 `quantumultx.conf` 的「住宅节点」使用节点名称正则筛选；正则仅用于识别名称，需核对筛选出的节点及实际出口。

普通代理和住宅代理按域名规则分流，候选分开管理：

```ini
代理IP = select,PROXY,policy-select-name=PROXY
```

普通代理分组不混入住宅节点。`PROXY` 跟随小火箭首页选中的节点，首页应选择普通专线（如极速专线），全局路由使用「配置」。如果首页改选住宅节点，普通代理规则也会跟随住宅出口，因此这条简化配置依赖正确的首页选择。

- 住宅域名规则 → `住宅IP` / `ChatGPT` / `Claude` → 指定住宅节点。
- 普通代理域名规则 → `代理IP` 或 `PROXY` → 首页选择的普通节点。
- 直连域名规则 → `DIRECT`。

Quantumult X 的普通代理分组同样仅保留 `proxy`，不嵌套「住宅节点」。

2026-10-22 按维护者要求，将 `ping0.cc` 与 `ip125.com` 放在同一住宅规则集中，用于通过住宅出口访问。这次规则变更对应提交 `ece5987`。

```ini
RULE-SET,https://raw.githubusercontent.com/zouhuigang/ss-rule/refs/heads/main/rules/family_ip.list,住宅IP
```

```ini

```

### 更新与检查

1. 更新客户端订阅的远程规则集。Shadowrocket 中确认 `family_ip.list` 已包含 `ping0.cc`；Quantumult X 更新正在使用的拆分版或融合版引用。
2. Shadowrocket 全局路由保持「配置」，首页选择普通专线；「住宅IP」分组独立选择实际存在的指定住宅节点。
3. 在客户端测试 `ip125.com`、`ping0.cc` 的规则，确认都命中住宅分组，并解析到指定住宅节点。
4. 访问两个网站，并结合连接日志核对实际出口。若仍显示普通专线，检查规则缓存、分组当前选择及是否存在更高优先级规则。

本次添加已检查三份规则文件的内容一致性和差异格式；尚未对 `ping0.cc` 完成客户端规则测试或实际出口验证。其他域名上的第三方请求不因本条后缀规则自动归入住宅分组。

## 修改时检查

1. 三个住宅分组保留上述五种名称的兼容性。
2. 候选及嵌套分组不含普通代理或直连出口。
3. 不引入自动切换到普通代理的策略。
4. README 和配置示例不再指导用户将住宅服务切换到「代理IP」。
