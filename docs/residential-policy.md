# 住宅节点策略约定

确认日期：2026-10-22。来源：仓库维护者明确要求。

## 核心原则

> 宁可用户无法使用，也不要使用普通代理或低质量节点。

`住宅IP`、`ChatGPT`、`Claude` 属于住宅策略，只允许手动选择指定住宅节点。不得为提高可用性添加 `代理IP`、`PROXY`、`DIRECT`、普通机场节点或其他普通代理分组作为候选或兜底，也不得通过嵌套分组间接引入这些出口。

所有住宅节点不可用时，应排查或恢复住宅线路，不能改走普通代理。此约束适用于配置文件、示例、生成模板及使用说明；后续维护必须保留。

## 支持的节点名称

名称按实际大小写书写，其中 `Ip` 为大写 I、小写 p：

- `专属纯净静态住宅节点`
- `专属纯净静态住宅Ip-连接线路1`
- `专属纯净静态住宅Ip-连接线路2`
- `专属纯净静态住宅Ip-连接线路3`
- `专属纯净静态住宅Ip-连接线路4`

这些名称是配置兼容约定，不代表仅凭节点名称就能验证出口的住宅属性或质量。使用者应确认实际出口符合要求。

## Shadowrocket 配置

`ss.conf` 中三个住宅分组使用相同候选列表，保留按服务独立手动选择：

```ini
[Proxy Group]
住宅IP = select,专属纯净静态住宅节点,专属纯净静态住宅Ip-连接线路1,专属纯净静态住宅Ip-连接线路2,专属纯净静态住宅Ip-连接线路3,专属纯净静态住宅Ip-连接线路4,policy-select-name=专属纯净静态住宅节点
```

`ChatGPT`、`Claude` 分组采用同样写法。默认选择旧名称，使用者需在分组中选择订阅里实际存在且可用的住宅节点；`select` 保持手动选择。

住宅节点失效或被服务封禁时，只能手动选择另一条确认可用的指定住宅线路，或等待修复。导入配置后，应检查三个分组的实际选中项；缺失节点时客户端的具体行为需在客户端验证，不能把配置候选列表视为已验证的断网保障。

## Quantumult X 与普通代理策略

Quantumult X 的住宅策略同样不得引入普通代理候选。当前 `quantumultx.conf` 的「住宅节点」使用节点名称正则筛选；正则仅用于识别名称，需核对筛选出的节点及实际出口。

普通代理分组仍可供其他服务使用。本约定限制住宅策略的出口，不要求删除仓库中的所有普通代理分组。

## 修改时检查

1. 三个住宅分组保留上述五种名称的兼容性。
2. 候选及嵌套分组不含普通代理或直连出口。
3. 不引入自动切换到普通代理的策略。
4. README 和配置示例不再指导用户将住宅服务切换到「代理IP」。
