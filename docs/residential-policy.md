# 住宅节点策略约定

确认日期：2026-10-22。来源：仓库维护者明确要求。

## 核心原则

> 宁可用户无法使用，也不要使用普通代理或低质量节点。

`住宅IP`、`ChatGPT`、`Claude` 属于住宅策略，只允许手动选择指定住宅节点。不得为提高可用性添加 `代理IP`、`PROXY`、`DIRECT`、普通机场节点或其他普通代理分组作为候选或兜底，也不得通过嵌套分组间接引入这些出口。

所有住宅节点不可用时，应排查或恢复住宅线路，不能改走普通代理。此约束适用于配置文件、示例、生成模板及使用说明；后续维护必须保留。

## 支持的节点名称

名称按实际大小写书写，其中 `Ip` 为大写 I、小写 p：

- `专属纯净静态住宅节点`
- `专属纯净静态住宅Ip-连接线路1`
- `专属纯净静态住宅Ip-连接线路2`
- `专属纯净静态住宅Ip-连接线路3`
- `专属纯净静态住宅Ip-连接线路4`

这些名称是配置兼容约定，不代表仅凭节点名称就能验证出口的住宅属性或质量。使用者应确认实际出口符合要求。

## Shadowrocket 固定住宅出口（2026-10-31）

本节取代 2026-10-22 的“正则筛选住宅节点及禁止连接候选，select=0 取首项”方案。该旧方案已出现住宅节点存在、三个住宅分组却选中禁止项的情况，不能再将候选顺序当作条件兜底。

### 稳定节点定义与固定引用

```ini
[Proxy]
# 公开模板的安全占位；私有配置必须用真实住宅节点参数替换这一行。
住宅固定出口 = socks5,127.0.0.1,1

[Proxy Group]
Claude = select,住宅固定出口,policy-select-name=住宅固定出口
ChatGPT = select,住宅固定出口,policy-select-name=住宅固定出口
住宅IP = select,住宅固定出口,policy-select-name=住宅固定出口
```

「住宅固定出口」是配置内的本地别名，不属于机场订阅。它只能绑定人工确认的住宅节点，不能绑定普通专线。五种历史节点名称继续作为迁移来源兼容，但不再用它们的排序来决定默认出口。

每个住宅分组只有一个固定候选，无测速、无自动换线，也没有单独的“禁止连接”候选。真实节点定义一直保留在设备私有配置中：线路断网时请求失败；原线路恢复后，新连接重试同一节点，应用可能需要刷新或重试。订阅更新或原节点重命名不会修改这份快照。如果供应商改变地址、凭据或住宅出口，需要人工核对后更新快照。

公开 `ss.conf` 不能包含真实凭据，默认固定出口指向本机关闭端口。仅下载公开模板不会获得可用的住宅连接；不可在 `127.0.0.1:1` 运行 SOCKS 代理。它是未配置时的阻断占位，不是可以自动恢复的真实出口。

### 私有配置填写

复制公开模板为设备私有配置，例如 `ss-residential-private.conf`。保留三个分组的固定引用，只将 `[Proxy]` 中「住宅固定出口」这一行的连接参数替换为确认可用的住宅节点参数：

```ini
[Proxy]
住宅固定出口 = vless,<住宅服务器>,<端口>,password=<UUID>,tls=true,<其他原始参数>
```

以上仅为格式示意，不能直接导入。必须完整保留原节点协议、传输方式、TLS/REALITY、公钥、短 ID 等参数，不要只改服务器地址。确认来源属于上述五种住宅名称之一，并核对真实出口。名称不能证明住宅属性。

真实节点参数只保存在设备或本地被忽略的 `.private/` 目录内，不得提交公共仓库。不要在公开 `ss.conf` 中填写 UUID、密码或完整订阅地址。

私有配置中移除整份配置的 `update-url`，防止远程公开模板覆盖真实住宅参数。后续配置改动需保留这一个本地定义后再合并；不要直接用公开模板整份替换。源节点地址或凭据变化时，由人工核对后更新固定出口，不自动选择其他节点。

本次任务范围为修改仓库配置和文档。除用户明确要求操作客户端外，不切换活动配置、节点或 VPN 连接，也不自动生成或部署私有配置。

### 本地域名规则与失败处理

- `ss.conf` 在 `[Rule]` 开头内置三份住宅清单的全部规则：`rules/family/Claude.list`、`rules/family/ChatGPT.list`、`rules/family_ip.list`。远程规则集未加载时，已有住宅域名仍优先匹配住宅分组。新增域名需同步本地副本并重发私有配置。
- `udp-policy-not-supported-behaviour = REJECT`：不支持 UDP 时拒绝，禁止转为直连。此设置也会影响其他分组的不支持 UDP 的节点。
- `close-if-proxy-chain-missing = true`：中转链缺失时关闭连接，不跳过中转。
- 全局路由必须保持「配置」；全局代理模式、关闭 VPN、模块覆盖等操作可能绕过本配置的域名约束，不应把本方案理解为系统级不可绕过的访问控制。

### 验证与边界

静态检查应覆盖：固定引用在同配置中有且仅有一个定义、住宅分组无其他出口、本地域名清单完整、UDP 和代理链关闭降级路径，且公开文件无真实凭据。

客户端验收要区分“规则解析”和“实际出口”：

| 场景 | 应观察的行为 |
|---|---|
| 正常访问 Claude/ChatGPT/ip125/ping0 | 规则指向住宅固定出口，连接日志及 IP 检测确认住宅出口 |
| 原住宅服务器暂时无法连接 | 请求失败，不能出现普通代理或直连连接 |
| 原住宅服务器恢复 | 新请求仍使用原固定节点；必要时应用重试 |
| 订阅更新或源节点改名 | 固定出口的配置参数不变 |
| 住宅远程规则集未加载 | 本地内置域名规则仍指向住宅固定出口 |

公开模板未填真实凭据时只能阻断。恢复及断网场景不能仅凭规则测试页宣称已验证，需控制故障并检查真实连接。

## Quantumult X 与普通代理策略

Quantumult X 的住宅策略同样不得引入普通代理候选。当前 `quantumultx.conf` 的「住宅节点」使用节点名称正则筛选；正则仅用于识别名称，需核对筛选出的节点及实际出口。

普通代理和住宅代理按域名规则分流，候选分开管理：

```ini
代理IP = select,PROXY,policy-select-name=PROXY
```

普通代理分组不混入住宅节点。`PROXY` 跟随小火箭首页选中的节点，首页应选择普通专线（如极速专线），全局路由使用「配置」。如果首页改选住宅节点，普通代理规则也会跟随住宅出口，因此这条简化配置依赖正确的首页选择。

- 住宅域名规则 → `住宅IP` / `ChatGPT` / `Claude` → 指定住宅节点。
- 普通代理域名规则 → `代理IP` 或 `PROXY` → 首页选择的普通节点。
- 直连域名规则 → `DIRECT`。

Quantumult X 的普通代理分组同样仅保留 `proxy`，不嵌套「住宅节点」。

### 更新与检查

1. 更新客户端订阅的远程规则集。Shadowrocket 中确认 `family_ip.list` 已包含 `ping0.cc`；Quantumult X 更新正在使用的拆分版或融合版引用。
2. Shadowrocket 全局路由保持「配置」，首页选择普通专线；「住宅IP」分组独立选择实际存在的指定住宅节点。
3. 在客户端测试 `ip125.com`、`ping0.cc` 的规则，确认都命中住宅分组，并解析到指定住宅节点。
4. 访问两个网站，并结合连接日志核对实际出口。若仍显示普通专线，检查规则缓存、分组当前选择及是否存在更高优先级规则。

本次添加已检查三份规则文件的内容一致性和差异格式；尚未对 `ping0.cc` 完成客户端规则测试或实际出口验证。其他域名上的第三方请求不因本条后缀规则自动归入住宅分组。

## 修改时检查

1. 五种来源名称继续兼容；三个住宅分组仅引用配置内始终存在的住宅固定出口。
2. 固定出口必须是人工确认的住宅参数；不得删除定义而保留引用，不得混入普通代理或直连。
3. 不引入自动切换到普通代理的策略。
4. README 不指导住宅服务切到普通代理；源住宅清单变更必须同步 ss.conf 内置副本。
5. 私有节点凭据不得提交，私有配置不得被公开模板整份自动覆盖。
